## 3. 关键决策回顾

### 3.1 音频方案：三轮迭代才定稿

| 轮次 | 方案 | 结果 |
|---|---|---|
| A | BGM 主导 + 统一打击音 | 效果不好，用户回滚 |
| B | 五个固定采样按键音 + 变调 | 效果不好，用户回滚 |
| C | **谱面带 MIDI，按下即按原音高实时合成** | 定稿 |

结论：音游的「按键音高」必须与谱面语义一致，否则玩家感知到的是噪声而非旋律。合成音色用自定义周期波（基频 + 递减泛音）+ 快速起音、中等衰减，才接近八音盒 / 古筝的听感。

### 3.2 半音如何塞进五条轨道

五声轨道只有 1 2 3 5 6，而民歌里有 4（fa）和 7（si）。最终方案：

- 谱面里照常记录 4 / 7 的真实 MIDI
- 标记为 `auto`：到点自动发声，**不下落、不判定**
- 玩家仍只按五条轨道

这样旋律完整、操作不额外变难。

### 3.3 点击偏移的根治

症状：反馈画面比实际触点高约 139 设计像素。

根因：Canvas 中心固定在设计分辨率中心，而输入按可见高度换算。

修复：`_syncCanvasSize()` 让 Canvas 尺寸、位置、相机 `orthoHeight` 与 `visibleSize` 三者对齐，输入改用 `camera.screenToWorld()` 反投影。修复后实测「点击坐标 → 音符中心」偏差为 0。

## 4. 经验总结

### 4.1 技术侧

1. **简谱映射必须查表**：`'12345'.indexOf()` 会把 5 映射到第 5 个位置、6 直接丢失，导致徵轨恒空。显式表是唯一安全做法。
2. **时间戳统一取整**：浮点累加会产出 `2666.666` 这类值，判定虽无影响，但数据不规范且难比对。
3. **Label 必须挂在独立子节点**：同一节点挂 Graphics + Label 会互相吞渲染。
4. **按钮文字挂在按钮节点下**：挂页面根节点时，翻页/隐藏后文字会残留。
5. **HUD 用位移隐藏而非 `active=false`**：微信下切换 active 可能丢失字形缓存，出现文字不显示。
6. **音频失败不要缓存 Promise**：一次初始化失败若把 rejected Promise 存下来，后续永远无法恢复。
7. **MISS 要有动画**：直接回收节点会让音符「凭空消失」，玩家无法判断是否漏接。

### 4.2 流程侧

1. **三层验证缺一不可**：类型检查抓结构错误，单测抓逻辑边界，模拟器抓真实渲染与交互。
2. **用运行时探针代替猜测**：在模拟器里 hook `createOscillator` 统计调用次数，直接证实「半音确实发声」，避免了盲目改代码。
3. **截图 + 像素测量定位视觉问题**：点击偏移就是靠放大截图逐像素对比才定位到 139px 这个具体数值。
4. **每轮改动后回归**：40 项单测在每次修改后全量重跑，累计拦下多次回归（如返回键被吞）。
5. **版本管理尽早接入**：git 初始化后，每次验证通过即 commit + push，任何一次误改都能回滚。
